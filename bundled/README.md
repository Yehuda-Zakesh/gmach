# רשימת התוכנות המובנות (bundled)

הקובץ `manifest.json` בתיקייה הזו הוא רשימת התוכנות ש**כל התקנה** של גמ"ח
תוכנה מסתנכרנת מולה אוטומטית — בלי קשר לתוכן שכל מנהל מוסיף ידנית אצלו.

## איך זה עובד בפועל

1. בכל הפעלה של האפליקציה (ברקע, לא חוסם את הפתיחה), ה-exe שולף את הקובץ
   הזה ישירות מ-GitHub:
   `https://raw.githubusercontent.com/Yehuda-Zakesh/gmach/main/bundled/manifest.json`
2. עבור כל פריט ב-manifest, האפליקציה בודקת אם הגרסה המקומית (השמורה
   ב-`data/database.json`, בשדה `extra.bundledVersion`) שונה מהגרסה ב-manifest.
3. **רק** אם יש הבדל — או שהפריט חדש — הקובץ מ-`downloadUrl` מורד
   ל-`data/software/bundled/` והרשומה בקטלוג מתעדכנת (או נוצרת) עם
   `"source": "bundled"`.
4. אם אין רשת, או שהבקשה נכשלת — האפליקציה פשוט ממשיכה לעבוד עם מה
   שכבר קיים מקומית. זו אף פעם לא שגיאה שחוסמת את הפתיחה.

## איך מוסיפים תוכנה מובנית חדשה

1. מעלים את קובץ ההתקנה כ-**Release asset** ברפו הזה (Releases → New
   release, או עריכת release קיים) — כדי לקבל קישור הורדה ישיר ויציב.
2. מוסיפים רשומה ל-`items` במבנה הבא:

```json
{
  "id": "unique-stable-id-לא-משתנה-לעולם",
  "name": "שם לתצוגה",
  "version": "1.2.3",
  "description": "תיאור קצר (אופציונלי)",
  "category": "קטגוריה (אופציונלי)",
  "instructions": "הוראות התקנה (אופציונלי)",
  "fileName": "installer.exe",
  "downloadUrl": "https://github.com/Yehuda-Zakesh/gmach/releases/download/<tag>/installer.exe"
}
```

3. `id` הוא המזהה הקבוע שמקשר בין ה-manifest לפריט בקטלוג של כל משתמש —
   **אסור** לשנות אותו לאחר הפרסום הראשון, אחרת ייווצר פריט כפול. `version`
   הוא מה שמשווים כדי להחליט אם צריך להוריד מחדש — כל שינוי בקובץ חייב
   להיות מלווה בהעלאת מספר הגרסה.
4. Push ל-`main`. תוך זמן קצר כל התקנה קיימת תזהה את העדכון בהפעלה הבאה
   שלה.

## הסרת תוכנה מובנית

הסרת רשומה מ-`items` **לא** מוחקת אותה אצל משתמשים קיימים (המערכת לעולם לא
מוחקת קבצים באופן אוטומטי) — היא רק מפסיקה לעדכן אותה. מחיקה בפועל היא
פעולה ידנית של המנהל המקומי דרך מסך הניהול.
